# 验证内网穿透配置是否成功

## 适用场景

当服务端和客户端配置都已完成，需要确认公网映射链路是否已经建立时，使用本模块。

## 前置条件

至少已知以下信息：

1. `server_addr`
2. 远端端口
3. 目标 `device_id`

默认验证协议为 `tcp`；如果后续映射类型发生变化，再按实际协议调整。

## 执行流程

1. 先向用户明确说明：接下来会调用内网穿透服务端的验证接口，在 VPS 侧检查指定协议和端口是否已进入监听状态；这里验证的是内网穿透服务是否已完成配置并开始监听，不是在验证服务端程序本身是否安装。
2. 调用 `openclaw_verify_frps`，传入协议 `tcp` 和远端端口。
3. 若验证结果显示未监听：
   1. 只允许调用一次 `clawwrt_restart_xfrpc` 重启目标路由器的内网穿透客户端，禁止重复重启。
   2. 再次调用 `openclaw_verify_frps` 检查同一协议和端口是否进入监听状态。
4. 若重启后仍未监听：
   1. 告知用户链路尚未建立成功。
   2. 引导优先检查认证密钥、服务端地址、服务端监听端口和防火墙放行情况。
   3. 不得直接宣称部署成功。
5. 若验证结果显示已监听：
   1. 明确告知用户：当前只证明监听已出现，不能直接等同于最终配置成功。
   2. 引导用户通过 `server_addr:远端端口` 做实际访问测试。
   3. 根据映射服务类型给出对应测试示例，例如 SSH 或 Web 访问。
6. 汇总最终结果，明确说明配置是否成功，以及成功时的访问入口。

## 规则

1. 先做可机器判定的监听检查，再让用户做实际访问测试。
2. 若第一次监听检查失败，只允许做一次客户端重启重试；第二次仍失败时，转入故障提示，不要无限重试。
3. 验证失败时，至少指出最可能的三个排查方向：认证密钥不匹配、服务端地址或端口错误、防火墙未放行。

## 成功输出

至少包含：

1. 监听检查结果
2. 是否执行过客户端重启
3. 实际访问测试结果
4. 实际访问入口
5. 验证结论
