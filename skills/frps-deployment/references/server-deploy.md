# 部署或修复 VPS 内网穿透服务端

## 适用场景

当 VPS 侧内网穿透服务端未安装、未运行，或运行中但认证密钥为空时，使用本模块。

## 固定入口

先调用：

1. `openclaw_get_frps_status`

## 执行流程

1. 先检查服务端当前状态；若仍是“未安装”“未运行”或“token 为空”，继续本模块。
2. 调用 `openclaw_deploy_frps`。
   1. 使用工具默认监听端口。
   2. token 由 Agent 自动生成随机字符串并传入；不要询问用户是否需要生成。
3. 部署后再次调用 `openclaw_get_frps_status`。
4. 若返回的 token 仍为空：
   1. 立即再次调用 `openclaw_deploy_frps`。
   2. 显式传入新的随机 token。
   3. 再次调用 `openclaw_get_frps_status`，直到确认 token 非空。
5. 服务端状态正常后，调用 `openclaw_get_vps_public_ip` 获取公网 IP。
6. 一次性向用户说明：
   1. 服务端监听端口
   2. 认证密钥
   3. VPS 公网 IP
   4. 云平台安全组或防火墙需要放行服务端监听端口对应的 TCP 入站流量
7. 若用户希望使用域名而非公网 IP，要求用户提供域名；否则默认用已获取的公网 IP 作为 `server_addr`。
8. 本模块完成后，再进入 `references/client-deploy.md`。

## 规则

1. 在服务端部署完成前，不询问任何客户端参数。
2. 本模块只负责 VPS 侧部署，不调用路由器侧客户端配置 API。
3. 不得自行猜测公网 IP；只能使用 `openclaw_get_vps_public_ip` 返回值或用户明确提供的域名。
4. 若部署失败，立即停止并报告错误，不进入客户端部署。
5. 部署成功不等于公网一定可访问；必须提醒用户检查云厂商安全组或外部防火墙。

## 成功输出

至少包含：

1. 服务端部署结果
2. 监听端口
3. 认证密钥
4. VPS 公网 IP 或用户确认的域名
5. 下一步建议：继续配置客户端
